# DeepScientist 前端改造 · 可行性验证报告

**验证对象**：`@researai/deepscientist` 1.5.17（Windows 原生运行）
**改造内容**：仅替换前端静态资源（品牌皮肤），不改任何业务代码
**验证时间**：2026-10-19
**结论一句话**：**前端改造本身是安全的，实测全部通过；但"原生 Windows 上完整跑通一次自治科研"目前不成立，卡点在运行时与 MCP 工具，不在前端。**

---

## 一、验证目标

把 DeepScientist 的前端改成"信通智研台 · 桂电信息与通信学院"品牌之后，需要回答三个问题：

1. 页面还能不能正常渲染、交互、切换语言？
2. 后端接口、课题创建与状态流转有没有被影响？
3. 能不能真的用它跑完一个完整课题？

## 二、改造范围（改了什么，没改什么）

| 类别 | 内容 | 是否触碰业务逻辑 |
|---|---|---|
| 注入 | `index.html` 追加 1 个 `<link>` 和 1 个 `<script>` | 否 |
| 样式 | `brand.css`（外部覆盖，不改原 CSS 包） | 否 |
| 文案 | `brand.js` 运行时替换文本节点（中英两套映射） | 否 |
| 素材 | 替换 `logo`、`hero/*.png` 等 10 张图 | 否 |
| 后端 | **完全未修改** | — |

原始文件已备份在 `my-ui/_backup/`（11 个文件），回滚命令：`python restore.py`。

**设计原则**：所有改造都是"叠加"，不删除、不重写原有 DOM 和脚本，因此理论上不可能改变业务行为。
本报告要验证的就是这个"理论上"到底成不成立。

## 四、发现的四个问题

这些问题**都不是前端改造引起的**，而是原生 Windows 环境本身的问题，但会直接影响"能不能用"。

### 问题 1：运行时指纹丢失导致服务启动死锁 ★★★

- **现象**：双击启动脚本后窗口一闪而过，`127.0.0.1:20999` 始终无响应。
- **日志**：`DeepScientist detected a runtime change and is rebuilding...` 后再无下文。
- **根因**：启动器判断运行时变化后，**先删除指纹文件** `runtime/bundle/python-stamp.json`，
  再删除 Python 环境重建；但重建动作被外部注入的批量删除保护钩子
  （`NODE_OPTIONS` 里的 `safe-delete` shim）拦截而失败。
  结果指纹已删、环境未建 → 下次启动又判定"有变化" → **永久死锁**。
- **处理**：清空 `NODE_OPTIONS` 后启动，让重建真正完成；必要时用 `uv sync` 补齐依赖。
- **建议**：官方应先删环境、成功后再删指纹；或把删除做成可恢复的改名。

### 问题 2：MCP 配置 TOML 转义 Bug（Windows 专属）★★★

- **现象**：codex 进程一启动就 `[Errno 32] Broken pipe`，连续重试 5 次全部失败。
- **根因**：`src/deepscientist/runners/codex.py` 在生成 MCP 配置时直接拼接路径：

  ```python
  f'command = "{sys.executable}"'
  ```

  Windows 路径 `D:\DeepScientist\...` 中的反斜杠在 TOML 里是转义符，导致
  整个 `config.toml` 解析失败（`missing escaped value`），codex 直接退出。
- **修复**：改为 `json.dumps(str(sys.executable))`，生成合法的转义字符串。
  补丁见 `patches/0001-fix-codex-mcp-toml-escaping.patch`。
- **说明**：这是**所有 Windows 用户都会踩的坑**，与前端无关。

### 问题 3：`shell_command` 工具在原生 Windows 上挂起 ★★★

- **现象**：修好 TOML 后模型能正常对话、能规划、能发起工具调用，
  但一旦调用 `shell_command`（底层执行 `bash -lc ...`）就再无返回，
  事件流停在 `runner.tool_call`，实测挂起 6 分钟以上。
- **影响**：agent 无法执行任何命令 → 不能写脚本、不能跑实验 → 内置自动流程走不完。
- **绕行**：本次实验改由本机 Python 直接执行同一份实验设计（见 `experiments/aliasing/`）。
- **说明**：官方文档明确写着"原生 Windows 支持仍处于实验阶段，强烈建议优先使用 WSL2"，
  本次实测印证了这一点。

### 问题 4：前端本地化残留（轻微）

- **首次引导弹窗** "Before you start" 全英文、无品牌（`images/04-first-run-onboarding.png`）；
- 课题卡片副标题 `Ready for your first instruction.` 未翻译。
- 这两处属于词典未覆盖，不是机制问题，补充映射即可。

## 五、结论

| 问题 | 结论 |
|---|---|
| 改前端会不会把 DeepScientist 改坏？ | **不会**。页面、弹窗、列表、接口、课题生命周期全部正常 |
| 改完能不能当日常工具用？ | **能，但仅限浏览、建课题、看文件**；"让它自动跑完一个课题"目前不行 |
| 卡点在哪？ | 不在前端，在 ①运行时自检死锁 ②TOML 转义 Bug ③Windows 下 shell 工具挂起 |
| 推荐做法 | 装 WSL2 跑 DeepScientist，前端皮肤原样迁移；或等官方修复 Windows 支持 |

## 六、风险与回滚

| 风险 | 说明 | 应对 |
|---|---|---|
| 升级 npm 包会覆盖皮肤 | `dist/` 被重装 | 重新执行 `python deploy.py` |
| 皮肤依赖 DOM 文本 | React 重渲染会覆盖文案 | 已用 MutationObserver + 兜底扫描 |
| 回滚 | — | `python restore.py` 还原 11 个原始文件 |
| 安全 | 服务只监听 `127.0.0.1` | 不要改成 `0.0.0.0` 暴露到公网 |

## 七、代码仓库

改造后的前端皮肤、实验产物、两份报告与修复补丁已整理为独立仓库，并已推送成功：

```
线上：https://github.com/mzxl-guet/sic-console-deepscientist    （私有仓库，38 个文件）
本地：D:\DeepScientist\sic-console-repo
```

仓库只包含**皮肤源码 + 工具 + 实验 + 报告 + 补丁**，不包含上游源码与 node_modules
（上游装完约 650 MB，无法也不应直接推上去）。

**完整性校验**：推送后用 Git 对象哈希（`sha1("blob <len>\0" + 内容)`）对 38 个文件
逐个与 GitHub 上的 blob SHA 比对，**38/38 全部一致**，图片二进制未被破坏。

### 7.1 推送过程遇到的问题（值得记录）

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 直连 `github.com` 100% 超时 | 该域名解析到 `20.205.243.166`，此 IP 在校园网被拦；同网段的 `api.github.com`（`.168`）却正常 | 挂 VPN 后 1.3 秒返回 200 |
| 换多个 IP、改 DNS 都无效 | 拦的是**域名/SNI**，不是 IP，改 hosts 也没用 | 只能走代理或 VPN |
| `winget install GitHub.cli` 失败（退出码 1602） | 需要 UAC 管理员授权被取消 | 改用绿色版解压即用 |
| `gh auth login` 设备码登录反复 `authorization_pending` | 授权页有两屏，只点 `Continue` 不算完成，还要点第二屏的 `Authorize` | 改用 Personal Access Token |
| 建库后首推返回 `409 Git Repository is empty` | 空仓库无法直接用 Git Data API 创建 blob | 先用 Contents API 放一个初始提交 |
| GitHub 连接器返回 `403 Resource not accessible by integration` | 连接器用的是受限的 GitHub App 令牌，没有建库权限 | 改用 PAT（`repo` 权限） |
