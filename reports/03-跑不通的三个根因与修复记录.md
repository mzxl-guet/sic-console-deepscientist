# 03 · 项目跑不通的三个根因与修复记录

> 结论先说：**不是网络问题，也不是你操作错了。** 是三个互相独立的故障叠在一起：
> 启动脚本传了个不存在的参数、Python 环境里有个包装了一半、以及 Windows 路径没转义。
> 三个都修掉之后，同样的课题 **90 秒**就跑出了完整结果。

---

## 一、你看到的三个现象

| 现象 | 你以为的原因 | 实际原因 |
|---|---|---|
| 双击快捷方式，浏览器打不开 | 没装好 / 网络问题 | 启动脚本把参数传错，程序打印一屏说明就退出了 |
| 打开网页后建了课题，一直显示"重试中" | 模型不行 / 额度不够 | codex 一启动就因为配置文件语法错误退出 |
| 偶尔跑起来，但卡在"执行命令"再也不动 | 电脑卡了 | 真正该用的命令工具崩了，退回到会死锁的 PowerShell |

这三个是**串联**的：修好第一个才能看到第二个，修好第二个才暴露第三个。所以之前每次只修一处，看起来就像"怎么都跑不通"。

---

## 二、根因一：启动脚本传了不存在的参数

**文件**：`D:\DeepScientist\start.cmd` 第 15 行

```bat
ds --home "D:\DeepScientist\home"
```

**问题**：启动器 `bin/ds.js` 的正常启动路径里**根本没有 `--home` 这个参数**。
`--home` 只出现在 `ds migrate` / `ds uninstall` 这两个子命令里。

**结果**：参数无法识别 → 启动器打印 logo、版本信息、帮助文本，然后**正常退出**（退出码 0）。
`start.cmd` 后面的等待循环轮询 60 次（2 分钟）都拿不到响应，最后报"启动失败"。

**证据**：

```
$ tail /tmp/ds-boot.log
  ds --tui                        Start the terminal workspace only
  ds --no-browser                 Do not auto-open the browser
  ds --status                     Show daemon health as JSON
  ...（全是帮助文本，没有启动守护进程）

$ netstat -ano | grep 20999
（空）
```

**修复**：删掉该参数。`start.cmd` 第 8 行已经设了 `DEEPSCIENTIST_HOME`，启动器会自动读。

```bat
rem 改前
ds --home "D:\DeepScientist\home"
rem 改后
ds
```

`stop.cmd` 同理，`ds --home "..." --stop` → `ds --stop`。

## 三、根因二：一个"装了一半"的包，让命令工具整体崩塌

这是最隐蔽的一个。

### 3.1 链条

1. DeepScientist 会给 codex 挂三个 MCP 服务：`memory`、`artifact`、`bash_exec`，
   全部通过 `python -m deepscientist.mcp.server --namespace xxx` 以 stdio 方式启动。
2. 这些服务要 `import mcp`，而 `mcp` 依赖 `pydantic-settings`，后者又依赖 `python-dotenv`。
3. 本机环境里 `python_dotenv-1.2.2.dist-info`（安装记录）**在**，
   但真正的 `dotenv/` 代码目录**不在** —— 这是之前一次 `uv sync` 被中断留下的半装状态。
4. `import mcp` 直接抛 `ModuleNotFoundError: No module named 'dotenv'`，
   三个 MCP 服务**启动即崩**，codex 一个都拿不到。
5. codex 于是退回自己的原生 `shell_command`（Windows 上就是
   `powershell.exe -Command "Get-ChildItem -Recurse -File ... | Format-Table -AutoSize"`）。
6. 这条命令在 4234 个文件上跑，输出量足以写满管道缓冲区；下游没有及时排空 → **死锁**，
   5 分钟没有任何返回。

### 3.2 证据

任务事件表里，整个课题只出现过 **2 次**工具调用：

```
  1  codex.list_mcp_resources
  1  shell_command
```

`bash_exec` 一次都没出现 —— 说明它压根不在工具列表里，不是模型"不想用"。

直接启动 MCP 服务的真实报错：

```
File "...\site-packages\pydantic_settings\sources\providers\dotenv.py", line 11
    from dotenv import dotenv_values
ModuleNotFoundError: No module named 'dotenv'
```

而 `uv pip check` 却报"全部兼容"——因为它只比对**元数据**，不检查文件是否真的存在。
**这是一个重要的排查教训：pip check 通过 ≠ 包装好了。**

### 3.3 修复

```bash
uv pip install --reinstall --python D:\DeepScientist\home\runtime\python-env\Scripts\python.exe python-dotenv
```

修复后三个服务的 `tools/list` 全部正常：

```
=== bash_exec ===  ['bash_exec']
=== memory    ===  ['write','read','search','list_recent','promote_to_global']
=== artifact  ===  ['record','checkpoint','git','prepare_branch', ... 共 32 个]
```

## 四、根因三：Windows 路径没转义，codex 一启动就退出

### 4.1 现象

课题状态一直是 `retrying`，失败原因是：

```
Runner `codex` failed on attempt 1/5: [Errno 32] Broken pipe
```

`Broken pipe` 的意思是"进程刚起来就死了，管道另一端没了"——它本身不含任何有用信息，
真正的错误被吞掉了。

### 4.2 根因

`deepscientist/runners/codex.py` 在生成 MCP 配置时这样写：

```python
f'command = "{sys.executable}"'
```

`sys.executable` 是 `D:\DeepScientist\home\runtime\python-env\Scripts\python.exe`。
直接塞进 TOML 双引号里，反斜杠没有转义：

```toml
command = "D:\DeepScientist\home\..."    # 非法：\D \h \r 不是合法转义
```

TOML 解析直接失败，codex 立刻退出 → 上层只看到 `Broken pipe`。

### 4.3 修复

```python
f'command = {json.dumps(str(sys.executable))}'   # 自动转义成 D:\\DeepScientist\\...
```

### 4.4 一个关键坑：补丁要打在哪一份代码上

这个项目是 `uv` 用本地路径安装的，`uv sync` 会把包**复制**到 `site-packages`：

```
实际 import 的：D:\...\python-env\Lib\site-packages\deepscientist\runners\codex.py
源码目录：      D:\...\node_modules\@researai\deepscientist\src\deepscientist\runners\codex.py
```

第一次只改了源码目录，结果重启后**毫无效果**——因为 Python 加载的是 `site-packages` 那份。
**两份都要改。**

## 七、遗留风险（下次出问题先看这几条）

1. **`uv sync` 或 `ds` 重建环境会覆盖 `site-packages` 里的补丁**，
   之后 codex 又会 `Broken pipe`。重跑一次 `fix_codex_toml.py` 即可。
   根治办法是给上游提 issue：`codex.py` 里应该用 `json.dumps` 而不是裸字符串插值。
2. **`pip check` 通过不代表包装好了**。环境被中断过之后，要用"直接 import"来验证，
   而不是看 `pip check`。
3. **原生 `shell_command` 仍然可用**，遇到大输出（几万行）仍可能慢或卡。
   指令里明确写"所有命令用 bash_exec"，可以减少触发概率。
4. **启动前必须 `set NODE_OPTIONS=`**，否则会被安全删除钩子拦住，卡在"重建环境"。
